# 情境插畫製作規範

每個主題的「情境圖」都是**一整張連續的插畫場景**，模仿日系圖解字典（例如 *In the Music Room*、*At the Beach*、*Around the House*、*In the City*）：物件放在它在現實中該在的位置，人物在場景裡活動，標籤用「編號＋英文＋KK＋中文」直接標在物件旁邊。

**絕對不要**把物件排成整齊的格子。要像一張畫：有地面、牆、天空、海、街道……物件放在桌上、架上、地上、水裡。

範例：`scenes/kitchen.svg` + `data/topics/kitchen.json` 的 `scene` 欄位（請先打開看，品質以它為最低標準）。

## 檔案

1. `scenes/<topicId>.svg`：背景插畫（純 SVG，不可引用外部檔案、字型、圖片）。
2. `data/topics/<topicId>.json` 裡加入 `scene` 欄位（其他欄位不要動，除非依下方規則換 emoji）。

## 背景插畫 SVG 風格

- `viewBox="0 0 1600 1000"`（字太多可用 1600×1100 或 1800×1100，`scene.w/h` 要一致）。
- 繪本扁平風：飽和但柔和的色塊，深咖啡描邊 `stroke="#6b4a36" stroke-width="4"`，圓角、`stroke-linejoin="round"`。可用 pattern 做磁磚、地板、點點牆紙；可用簡單漸層做玻璃/金屬。
- 畫出**場景本身**：房間（牆、地板、窗戶、家具）、戶外（天空、雲、山、草地、道路、海浪、沙灘）、建築剖面等。家具和大型物件（冰箱、櫃子、黑板、溜滑梯、房子、公車站……）直接畫在 SVG 裡。
- **左上角約 x<430、y<300 的區域會被四分之一圓標題蓋住**，那裡只放背景（牆、天空），不要放物件或標籤。
- 畫面要有前景、中景、背景的層次感，留出放標籤的空白處。
- 不要在 SVG 裡寫文字（招牌字可以用很短的英文，但盡量不用）。

## `scene` 欄位格式

```json
"scene": {
  "w": 1600, "h": 1000, "bg": "scenes/kitchen.svg",
  "items": {
    "pot":          { "x": 720, "y": 560, "s": 70, "lx": 720, "ly": 410 },
    "refrigerator": { "box": [1376, 176, 200, 694], "lx": 1476, "ly": 690 },
    "stove":        { "box": [808, 532, 196, 30], "lx": 906, "ly": 290, "line": [906, 538] }
  },
  "people": [["🧑‍🍳", 1176, 966, 156], ["🐈", 1312, 972, 64, true]],
  "bubbles": [{ "x": 470, "y": 770, "w": 300, "tail": "bl" }, { "x": 1250, "y": 770, "w": 230, "tail": "bl" }]
}
```

- `items` 的 key 必須是該主題 `words` 中 **type 不是 "phrase"** 的每一個 `en`（全部都要放，一個都不能少；片語不放）。
- 物件兩種放法：
  - **emoji 物件**：`x, y` = emoji 的**底部中心**（放在桌面、地面、架子上時，y 就是那個表面的 y）；`s` = emoji 大小（畫布像素，常用 40–110；大型物件大、小物件小，要符合真實比例感）。可加 `"flip": true` 左右翻轉、`"r": 15` 旋轉角度。
  - **畫在背景裡的物件**：`box: [x, y, w, h]` = 可點擊範圍（就是你在 SVG 裡畫它的位置）。emoji 不適合、太小、或物件是家具/建築/地形時用這種。
- 標籤：`lx, ly` = 標籤**頂部中心**（`la: "l"` 時為左上角、`la: "r"` 時為右上角）。標籤高度約 60px（英文一行＋KK＋中文），寬度約「字母數 × 13 + 40」px。
  - 標籤盡量放在物件正下方或旁邊空白處；擠不下時放遠一點並加 `"line": true`（自動連到物件中心）或 `"line": [x, y]`（連到指定點），畫出虛線引線。
- `people`：場景裡的人物，**一定要用繪本人物產生器（`js/characters.js`）畫的全身人物，不要用 emoji 人頭**。格式：
  `{ "p": { 人物參數 }, "x": 腳底中心x, "y": 腳底y, "h": 身高(畫布像素，小孩約 260–340，大人約 340–420), "flip": 是否左右翻轉 }`
  人物參數（全部可選）：
  - `hair`：`short` `spiky` `bob` `pigtails` `ponytail` `bun` `long` `curly` `grandpa` `grandma`；`hairColor`：色碼
  - `skin`：`light` `tan` `brown` `dark`
  - `shirt`、`pants`、`skirt`（有 skirt 就穿裙子）、`shoes`：色碼；`stripe`：衣服條紋色；`coat: true`（醫生/白袍前襟）；`apron`：圍裙色
  - `pose`：`stand` `wave`(揮手) `talk`(說話伸手) `hold`(雙手胸前拿東西) `cheer`(雙手舉高) `point`(指向) `hips`；`sit: true` 坐姿腿
  - `face`：`smile` `talk` `laugh` `wow`；`eyes`：`dot` `happy` `wink`
  - `acc`：配件陣列 `chefhat` `cap` `glasses` `bow` `nursecap` `helmet`；`accColor`：cap/helmet 顏色
  - `holding`：拿在胸前的 emoji（例如 `"🎈"`，搭配 `pose: "hold"` 或 `cheer`）
  可用 `http://localhost:8765/tools/people-preview.html` 預覽。每個場景放 2–5 個人物，衣服顏色要搭配場景、彼此不同，姿勢要和場景互動（說話的人用 talk、對著物件 point…），對話泡泡的尾巴指向說話的人。
  動物或小型生物仍可用 emoji 陣列：`["🐈", x, y底部, 大小, 是否翻轉]`。
- `bubbles`：依序對應 `sentences[0]`、`sentences[1]` 兩句話。`x,y` = 泡泡左上角，`w` = 寬度（約 230–340）。`tail` = 尾巴位置 `bl`/`br`（下方左/右）或 `tl`/`tr`（上方），要指向說話的人。
- emoji 只用單一字元或已確認能正常顯示的組合；**家庭組合類 ZWJ（👨‍👧、👨‍👩‍👧 等）在部分裝置顯示成方框，禁止使用**。截圖時看到方框就換掉。
- 若某個單字目前的 `emoji` 明顯不像該物件（例如 whisk 用 🥚），可以改成「畫在背景裡 + box」，或把該 word 的 `emoji` 換成更貼切的單一 emoji。

## 抽象主題怎麼辦

數字、顏色形狀、感受、打招呼、禮貌用語、時間月份、學科、方位、日常作息、職業、興趣……也一樣要做成**一個具體場景**，再把單字安排進去：
- 數字 → 例如市集/玩具店/運動會：數字畫成門牌、價格牌、號碼布、時鐘、計數的物品（用 box 指向畫出的數字牌）。
- 感受 → 遊樂園/教室裡表情不同的小朋友（用表情 emoji 當人物頭像放在畫出的身體上，或直接用表情 emoji）。
- 打招呼/禮貌用語 → 校門口、商店裡，人物之間互動，單字標在對應的人物旁。
- 方位 → 房間裡的貓在箱子上、下、裡、旁邊……
發揮創意，但每個單字都要對應到畫面上一個看得懂的東西。

## 檢查（每個主題都必須通過）

專案根目錄已有 `python3 -m http.server 8765` 在跑（若沒有就自己啟動）。

```bash
node tools/scene-check.cjs <topicId> <輸出資料夾>
```

會輸出桌機截圖與手機截圖，並列出：缺少的單字、標籤重疊、標籤蓋住物件、物件重疊、超出畫面、被標題蓋住……
- **必須修到顯示 `OK — no issues`**。
- 然後**一定要用 Read 打開截圖親眼看**：場景是否像一張完整的繪本插畫？物件位置是否合理（杯子在桌上、魚在水裡、雲在天上）？標籤是否清楚對應物件？畫面是否均衡、沒有大片空白或擠成一團？看到不好的就改，改到滿意為止。
- 不要執行 `tools/build-index.mjs`、不要 git commit（由主持人統一處理）。
